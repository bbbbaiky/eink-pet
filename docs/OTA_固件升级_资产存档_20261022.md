## 一、这套功能现在长什么样（用户视角）

- 入口只有两处（都已实测可用）：
  1. **设置 → 第 2 页 →「固件升级」行**（行尾显示当前版本）
  2. **关于页底部「检查版本」按钮**（`g_about_btn == 1` → `ota_enter()`）
- 进去先到 **升级方式选择页**：`TF 卡` / `网页` 两行（BOOT 移光标 / POWER 确认）。
- 两条路最终都写**非运行槽**（`ota_1`），校验通过才切启动分区；失败不切，旧固件照跑。

## 二、页面清单（8 页）

| page_t 枚举 | 用途 | 底图来源 |
|---|---|---|
| `PG_OTA_SEL` | 本地升级选择（TF / 网页 两行） | **程序绘制**（无底图） |

| `PG_OTA_NEWEST` | 已是最新（+「返回」） | **ui.bin 槽 48**（`UI_OTA_NEWEST`） |
| `PG_OTA_PROG` | 正在写入（进度条，锁输入） | **ui.bin 槽 49**（`UI_OTA_PROG`） |
| `PG_OTA_OK` | 升级完成（3 秒后自动重启） | **ui.bin 槽 50**（`UI_OTA_OK`） |
| `PG_OTA_FAIL` | 升级失败（3 秒回设置；原因写正文） | **ui.bin 槽 51**（`UI_OTA_FAIL`） |

- 两版**各有一份 `page_t` 枚举**（`#if TOUCH_DEMO` / `#else`），**必须同值同序**，改动要成对。

## 四、分区占用（这是想下线它的真实动机）

当前分区表（`fw_touch/partitions.csv`，两版同源）：

```
nvs      0x009000    24 KB
phy_init 0x00F000     4 KB
otadata  0x010000     8 KB     ← OTA 专用
ota_0    0x020000  2048 KB     ← app
ota_1    0x220000  2048 KB     ← OTA 专用（一直空着）
assets   0x420000  3776 KB     ← 图片/字体/i18n
```

- **OTA 独占总计 ≈ 2.06 MB**（`ota_1` 2 MB + `otadata` 8 KB）。
- 下线后可把这段并给 `assets`（现 3.69 MB → 约 5.7 MB），或给 app 扩容。
- ⚠ 改分区表后必须跑 `bash build2.sh migrate` / `bash build2_touch.sh migrate`（连表 + app + assets 一起写，**保 NVS**）。

## 五、将来"下线"要摘的点（逐条核对）

1. `page_t` 枚举：**两版各删 8 项**（`PG_OTA_SEL/WEB/CHECK/FOUND/NEWEST/PROG/OK/FAIL`），删除后两版顺序仍要一致。
2. `PAGE_HINT[]` 里对应条目（含末尾 `_Static_assert` 的上界常量 `PG_xxx + 1`）。
3. `page_render()` 两处 `switch` 里的 8 个 `case`（触屏/按键各一份）。
4. 按键处理：`boot_click` / `boot_long` / `power_click`（两版各一套）里这些页的 case；`page_is_leaf()` 的判定。
5. `ota_enter()`（`main.c` 约 13888）与两个入口：设置第 2 页「固件升级」行、关于页「检查版本」按钮（`main.c` 约 20046）。
6. `draw_ota_*` 六个绘制函数 + `g_ota_sel` / `g_about_btn` 相关状态。
7. `common/ota_up.c` / `ota_up.h` 整个删除；`net_prov.c` 删 `POST /upgrade` 路由 + `ota_web_*` 调用 + 相关 httpd 栈调整。
8. `ui.bin` 槽 46～51 **不必删**（留着不占运行内存，只是 assets 里的 6×5000B）；将来想给别的新页用，直接改 `UI_OTA_*` 宏指向即可 —— 这也是"快速接回"的关键。
9. 分区表：删 `ota_1` 行可回收 2 MB；`otadata`(8KB) 建议**保留**（IDF 的 OTA 机制依赖它存在，留着无害）。
10. 重新生成 `partition-table.bin` 并用 `migrate` 模式烧一次（**切勿用整片擦除**，会丢 NVS 配置与 WiFi）。

## 七、两条踩过的坑（别重犯）

1. **`esp_ota_begin()` 拒绝以"正在运行的分区"为目标**（`ESP_ERR_OTA_PARTITION_CONFLICT`）⇒ 单槽方案**必然**升级失败（表现为「开写失败」）。所以只要保留 OTA，就必须保留第二个 app 槽。
2. **TF 路交付物 = 单个 `.bin`**：版本号从 bin 内嵌 `esp_app_desc` 读，`version.json` 已彻底作废（2026-10-19）。别再把"文件夹 + version.json"那套捡回来。
